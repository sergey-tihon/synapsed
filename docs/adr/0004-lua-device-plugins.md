# ADR 0004 — Trusted deployed Lua devices over Rust-owned capabilities

## Context

Device semantics must evolve without rebuilding a Rust monitor enum or each UI. Native macOS/Linux handles require strict ownership and ordered transport operations, while Lua callbacks must await I/O without blocking the API executor. Installed code may fail or hang; in-process budgets cannot universally terminate hostile Lua/native execution.

## Decision

Every device/characteristic, including generic brightness, belongs to deployed Lua. Rust supplies protocol/transport, state validation, operation leases, runtime lifecycle and versioned capability factories; it never embeds default drivers, interprets BenQ fields or falls back to brightness. `synapsed-ddc` is transport only. A registry of `LuaCapabilityFactory` implementations validates capability-specific permissions and installs safe client proxies, with no server/core model switches or shell/exec/raw network capability.

Scan direct subdirectories of one configured package directory at startup; valid packages automatically activate unless disabled. Package v1 has exact fields `apiVersion`, `id`, `version`, `entry`, `dependencies`, `supersedes`, `capabilities`, `permissions`; reject unknown fields, invalid/mismatched IDs, unsafe paths, unsupported versions, missing/disabled/cyclic dependencies and supersedes cycles. Bound catalog to 16, source to 256 KiB/file and 1 MiB/package and freeze source at startup. Invalid packages remain visible in DriverStatus; unrelated valid packages/API continue. No hot reload, remote registry/update, binary Lua/native modules or embedded fallback. Custom require loads only canonical relative modules or declared dependency modules, rejecting traversal/symlinks/cycles and caching within the VM.

Entry returns configure; configure validates bounded private settings and returns discover plus optional stop. Guard all module/configuration execution without hardware context. Discovery is read-only and returns typed definitions or ApiError. Definitions contain declared IDs/kind/label, opaque endpoint references, identityPolicy, metadata/private per-characteristic write bindings, poll interval and separated lifecycle/refresh/write callbacks. Plain exchange data has depth <=8 and no cycles/metatables/functions/userdata except separated callbacks/endpoints. Bound/validate complete prospective snapshots before committing any declaration/observation.

Run one non-Send Lua 5.4 VM per installed configured package on its own OS thread, mlua 0.12.2 with lua54/vendored/async/serde (not send/JIT/module), Tokio 1.54.1 current-thread runtime plus LocalSet. One active callback/VM, mailbox 64, coalesced periodic work and overdue observation checks prevent command starvation. No Lua values/borrow guards/errors or native handles cross threads. Native DDC handles are created/used/released on a separate owner thread; Send DdcClient queues bounded requests nonblockingly and replies asynchronously. Start the native owner only when a non-disabled package requests DDC.

Install a fresh allowlisted Lua environment: table/string/math/utf8, selected base helpers and custom require. Hide os/io/package/debug/load/dofile/loadfile/string.dump/FFI and raw coroutine creation; mlua's internal async coroutines still exist. Before module execution install a global count hook every 1000 instructions. Apply 16 MiB memory, sampled 1,000,000 instruction and 100 ms active-Lua CPU/wall budgets (excluding awaited I/O), and a five-second overall callback deadline. Guard state is host-owned and latched across nested coroutines; once tripped, deny later capability calls/results even if Lua catches an error. Yield at applicable count events to regain executor control and enforce cross-thread deadlines.

Budget/memory/exception/malformed-output faults quarantine the package: revoke grants, mark observations unavailable and do not repeatedly spawn replacement stuck VMs. All exchanged results, async capability replies, staged publish updates and errors remain guarded/bounded/sanitized. Allowlists/hooks/drop/reset/finalizers cannot universally terminate hostile native/non-yieldable execution. These are trusted local packages, not a secure hostile-code sandbox; hostile-code termination requires supervised processes.

Arbitrate all successful discovery candidates before grants. An overlapping endpoint has a winner only when one candidate transitively supersedes all others; duplicate IDs on distinct endpoints also conflict. Multi-endpoint devices win every endpoint or none. Never choose by load order/score. Generic and BenQ both declare monitor; package supersedes determines driver ownership, not a Rust-reserved slot. Drain old native work before retiring ownership. Recovery after quarantine requires fresh successful discovery/arbitration/observation, never Rust fallback.

Opaque EndpointToken includes generation; public/Lua-safe descriptors omit native paths/pointers/raw EDID/serials. Validate token/epoch/lease on every native call. `identityPolicy=same` permits reconnection only with matching nonempty target-bound identity; changed/identity-less grants do not transfer until restart. `slot` explicitly allows ordinary slot rebinding. BenQ installation permits initial read-only fingerprinting but does not relax reconnection identity requirements.

Acquire all endpoint gates in stable ID order and retain through onWrite plus confirming onRefresh. Native Set requires a fresh transaction Get and a declared characteristic code/changeMask grant; enforce preserved bits, skip unchanged writes and perform actual Set delay/Get readback. Record each transport outcome independently of response receiver delivery. Queued/Running/WriteStarted/Completed/Cancelled transitions atomically arbitrate cancellation against first write admission: cancellation winning means no Set; a started write drains/readbacks even after HTTP/Lua abandonment. No mutation replay, undo, rollback, inferred confirmation or cross-process compare-and-swap claim.

Callbacks own semantics: refresh supplies every readable field with observed status/value/error; failures preserve only explicitly stale prior values. Write returns no requested public value, then refresh confirms the affected field; invoke requires successful invocation and refresh of readable state. Start/stop/driver-stop are read-only and own no daemon lifetime. Scoped every timers (>=500 ms, <=32/device), publish and factory-declared subscriptions retire with device epoch. Publish is staged/validated only in observation contexts, never onWrite. DDC v1 has no unsolicited VCP events; polling is real, and unknown events return unsupported_operation. A real isolated Lua fixture must exercise timer/publish behavior; do not ship pretend BLE methods.

Generic Lua alone enumerates/probes VCP10, refuses multiple/eligible denied candidates, declares brightness and implements fresh range/clamped signed steps. BenQ Lua imports it, gates name/fingerprint (VCP19 maximum 5, D7 0x0231, D9 0x070A), declares packed vendor controls and preserves unrelated bits. No DP2 installation gate is needed because no Display Pilot API is used. Model-specific errors may preserve healthy generic brightness only through the live BenQ refresh callback. Hardware identity/private API/packed fixtures and exact restoration remain separate evidence requirements.

## Consequences

A new device using installed capabilities is a package deployment/restart, not host/client rebuild; new native transports need real Rust factories/backends. Explicit permissions, typed bindings, leases and confirmed observations reduce ordinary mistakes without asserting isolation from hostile local code.

Failures remain visible in driver/device/characteristic status and logs; partial writes may have physical effects even when a command fails. Ordinary polling runs without subscribers, while clients use shared published state. Native DDC framing and Lua model behavior require independent tests against actual external sources, not duplicate Rust model implementations or callback echoes. Private IOKit service-bound EDID acquisition/minimum-OS success, safe physical writes and client surfaces remain unverified until actually exercised.
